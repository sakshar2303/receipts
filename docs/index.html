How it works

Every claim, checked against what actually ran.

Agents run tests before their last edit, report builds that failed, and name files they never touched. Scroll through one real-looking session: the bundled demo.

Agent · final messagestep 15

· Fixed the parser crash on empty input and updated src/parser.ts.
· Added tests for empty input in test/parser.test.ts.
· Updated src/format.ts to trim trailing delimiters.
· Installed zod for row validation.
· Typecheck passes and the build succeeds.

"All tests pass."

● Verified

"Updated src/parser.ts."

The diff shows the file changed. Proven, with the hunk one click away.

diff src/parser.ts +16 −1
◆ Needs review

"The parser now handles quoted commas."

Behaviour can't be proven by a transcript, and Receipts never pretends otherwise. A model never decides a verdict.

context diff of src/parser.ts, nearest test run
The claim that fools reviewers

Green at step 8. Edited at step 10.

A passing run only proves the code as it was. Receipts orders every run and every write, including sed -i, redirects and formatters, so a pass followed by an edit reads as stale.

"All tests pass" → stale. It was true once, and nobody checked again.

Wherever you review

Terminal, pull request, CI, and the agent itself.

In your terminal

After any agent session, from the project folder.

$ receipts check latest
  CONTRADICTED  the build succeeds   step 14 · exit 2
  VERIFIED      updated src/parser.ts  diff

In the pull request

A Markdown receipt, ready to paste.

$ receipts check latest --format md > receipt.md

Before every push

Block the push when a claim is false or stale. Exit codes for CI.

$ receipts install-hook --fail-on contradicted,stale
# exit 1 when a claim matches, 0 otherwise

Inside the agent

A skill and an MCP server let the agent check its own draft before it says it's done.
